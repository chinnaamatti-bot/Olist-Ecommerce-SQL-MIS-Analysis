# 📦 Olist E-Commerce Logistics & Fulfillment Performance Analysis

## 📊 Project Overview
This repository contains a comprehensive, production-ready SQL analytics project focused on **Supply Chain Optimization, SLA Management, and Management Information Systems (MIS) Reporting**. Using the public **Olist Brazilian E-Commerce Dataset**, this project maps out the core responsibilities of a Logistics MIS Analyst by converting over 100,000 rows of raw transactional and operational logs into high-impact corporate strategy.

The entire analysis is optimized for a **PostgreSQL** environment to resolve critical logistical dimensions: carrier Service Level Agreement (SLA) breaches, regional fulfillment center dispatch efficiencies, geographic shipping cost optimization, and macro demand forecasting.

---

## 🛠️ Tech Stack & Database Architecture
* **Database Engine:** PostgreSQL
* **Interface Tool:** DBeaver / Enterprise SQL Editor
* **Data Schema Model:** Relational Star-Schema Ingestion

### 📋 Core Tables Analyzed:
* `olist_orders_dataset`: Tracks order status, transactional approval gates, and carrier shipping/delivery logs.
* `olist_order_items_dataset`: Contains granular line-item prices, seller mappings, and specific regional freight valuations.
* `olist_customers_dataset`: Identifies customer demographic attributes, regional postal clusters, and geographic states.

### 📝 Operational Data Engineering & Data Cleaning Note
During database ingestion, operational milestones were imported from raw CSV formats as text fields (`character varying`) containing empty string padding (`""`). To ensure enterprise-grade stability and eliminate runtime arithmetic crashes, the analytical scripts utilize:
1. **Explicit Data Type Casts:** Converting raw string records via `::timestamp` and `::numeric` on the fly.
2. **Text Validation Filtering:** Implementing structural exclusions (`<> ''` and `IS NOT NULL`) to bypass unpopulated columns.
3. **Advanced Time Functions:** Using PostgreSQL-native `EXTRACT(DAY FROM...)` and `TO_CHAR()` features to replace non-compatible functions like `DATEDIFF` and `DATE_FORMAT`.

## 📈 Executive Summary: 3-Phase Operational Breakdown

### 🔍 Phase 1: Carrier Performance & SLA Tracking
* **Objective:** Audit the health of the fulfillment pipeline and isolate delays against promised delivery windows.
* **Core Metrics Evaluated:**
  * Total pipeline volume categorization by current lifecycle status.
  * Delivered orders in 'Sao Paulo '
  * State-by-state freight cost averages to pinpoint expensive shipping zones.
  * Exact calculation of delivery variance to isolate severe customer promise breaches.

### 🚛 Phase 2: Hub Efficiency & Strategic Customer Ingestion
* **Objective:** Evaluate internal warehouse dispatch speeds and group customer order profiles to manage physical packaging constraints.
* **Core Metrics Evaluated:**
  * Segmenting fleet performance logs into clean, qualitative report cards (`On-Time`, `Minor Delay`, `Critical Delay`).
  * High-revenue geographic center tracking (Top 5 customer cities) to target localized micro-fulfillment investments.
  * Bulk-fulfillment load identification by isolating orders containing total items above the global marketplace baseline average.

### 📊 Phase 3: Financial Optimization & MoM Demand Forecasting
* **Objective:** Track moving logistics liabilities per user and evaluate macro-demand fluctuations for upcoming fleet asset allocation.
* **Core Metrics Evaluated:**
  * Cumulative running totals of freight expenditures over historical timelines per customer to measure the Logistical Lifetime Cost (LCO).
  * Regional carrier hand-off efficiency rankings across different states using `DENSE_RANK()` window arrays.
  * Month-over-Month (MoM) net volume variations using `LAG()` analytics to enable predictive capacity planning ahead of seasonal spikes.

## 💡 Key Business Takeaways from the Analysis
* **SLA Risk Mitigation:** Proactively catches "Critical Delay" delivery groups before customer dissatisfaction translates to negative platform reviews.
* **Geographic Cost Reduction:** Provides data-driven backing to establish local warehouse spaces in outlying high-freight states, lowering customer transaction friction.
